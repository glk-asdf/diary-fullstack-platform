## 1. 你已经有什么，还缺什么

转全栈不是「从零学一门新技术」，而是**把已有的工程直觉迁移到陌生生态**。所以先看清哪些能力可以直接迁移：

| 全栈能力 | 你的现状 | 缺口 | 在哪补 |
|---|---|---|---|
| HTTP / 接口约定 | ✅ 熟悉（你天天调接口） | 从「消费接口」变成「设计接口」 | 模块 02、04 |
| 数据建模 | 🟡 会用 TS 定义类型 | 关系模型、索引、事务 | 模块 05 |
| 异步与并发 | ✅ Promise / async | Java 线程模型、连接池 | 模块 03 |
| 类型系统 | ✅ TS 泛型 / 联合类型 | Java 泛型擦除、受检异常 | 模块 01 |
| 模块化 | ✅ ESM / npm | 包、依赖注入、Spring 容器 | 模块 01、02 |
| 构建与产物 | ✅ Vite / npm scripts | Maven、多阶段镜像 | 模块 01、06 |
| 调试 | ✅ 浏览器 DevTools | 后端日志、SQL、容器 | 模块 03、07 |
| 部署 | 🟡 会上线静态站 | 容器编排、反向代理、卷与网络 | 模块 06 |
| 安全 | 🟡 知道 XSS | JWT、密码哈希、越权、密钥管理 | 模块 04 |
| 线上排障 | ❌ 基本没做过 | 分层定位、日志、健康检查 | 模块 07 |

**一句话结论**：你最缺的是**「数据如何持久化」「进程如何被编排」「出问题如何定位」**这三件事，而它们恰好是模块 03 / 06 / 07 的主题。

## 4. 学习方法（沿用前端那份文档的三步法）

每个知识点都按同一节奏：**先看 JS 世界怎么做的 → 再看这里怎么做 → 最后动手改一处并验证**。

```text
读：打开文中指出的具体文件，对照「JS/TS 写法 ↔ 这里写法」
跑：执行文中命令，核对「应该看到什么」
改：按练习题改一处，验证后改回
```

### 三条过来人建议

1. **不要先学「Java 语法大全」**。你的目标不是写 Java，是**读懂并小改**这个项目的 Java。够用就停。
2. **每个模块都要求你产出一个「能跑的东西」**（一个新的接口、一条新的 SQL、一次成功的恢复）。**只读不写，学完就忘。**
3. **错误信息是你的老师**。Java 的编译错误比 JS 啰嗦但精确得多——附录里专门整理了「常见编译错误解读」，遇到报错先查那里。
